# M2: Printable finite-basis substitution certificates

Temporary milestone note. Delete this file once M2 is achieved.

## Goal

Turn the finite beta-basis certificate from a Lean `Prop`-level relation into
printable data that can emit checked Core proof terms.

Target pipeline:

```text
HOL/contextual formula
  -> Lean translation
  -> Type-valued Core proof AST
  -> .cor statement plus proof term
  -> corecheck
```

`SubstEquiv` remains the specification theorem. Printable evidence must be a
separate data structure in `Type`; it cannot be recovered from a `Prop` proof in
Lean.

## Current status

M2.4 is complete for the known-good bridge suite.  The generator emits and
corechecks point bridges, atom/connective binder cleaners, `Forall_exMemPhi*`,
and `Forall_exUnion*`.

M2.5 is in progress.  `formalization/ContextualHOL/SubstEvidenceBuilder.lean`
contains the first formula-driven evidence builder.  The builder is now
parameterized by a `SubstShape`; the current live shape is `smap`, but the
formula recursion no longer hard-codes `smap` internally.  It recursively
handles:

- atom leaves of the form `R(w, a)`
- unary predicate leaves of the form `phi(w)`
- `and`, `or`, `imp`, `iff`, and `not`

The generator now emits checked formula-driven examples for `phi(w)`,
`R(w,a) or R(w,b)`, `R(w,a) iff R(w,b)`, and `R(w,a) and phi(w)`.  It also
emits checked quantifier-shell examples for `forall u. R(u,a)` and
`exists u. R(u,a)`, using `Forall_reindex` / `Exist_reindex` with the lifted
`smap` rendered explicitly as a point function.

The first full quantifier-cleaning examples now corecheck too:
`generated_formula_smap_forallAtomClean` and
`generated_formula_smap_existAtomClean`.  The first recursive quantified body
example also corechecks: `generated_formula_smap_forallAtomPhiClean` for
`forall u. (R(u,a) and phi(u))`.  These use the intended three-stage shape:

```text
Forall_reindex / Exist_reindex shell
  -> ctx-lifted atom cleanup under the quantified body
  -> Forall_ForallCong / Forall_ExistCong
```

This required adding the first finite ctx-lifted beta slice to `beta_basis.cor`:
`Forall_ctx_sub2_reindex_beta`, `Forall_ctx_fst_pair_beta_left`,
`Forall_ctx_const_comp_beta_right`, `Forall_ctx_unary_reindex_beta`,
`Forall_ctx_fst_pair_unary_beta_grouped`, `Forall_ctx_and_reindex_beta`,
`Forall_ctx_andCong`, and the logical glue `Forall_ctx_iffTrans_apply`.

The remaining M2.5 gap is general recursive prefix-context evidence.  We have the
atom, unary predicate, and `and` cases under one prefix context; the builder
still needs prefix versions for the other formula constructors (`or`, `imp`,
`iff`, `not`) and then nested quantifier bodies.

## M2.1 Machine-readable basis map

Add `formalization/ContextualHOL/BasisMap.lean`.

Define a `BasisName` enum and make `BasisName.coreName` the single source of
truth for Core proof constant names. The whitelist must include names from:

- `ma1/beta_basis.cor`
- beta-shaped infrastructure still in `ma1/classical_first_order_logic_new.cor`

Important non-`beta_basis.cor` names:

- `Forall_reindex`
- `curry_uncurry`
- `RelEqExt`
- selected logical/fiber glue used by emitted proof terms, such as
  `Forall_mono`, `Forall_iffSym`, `Forall_iffTrans`, `imply_elim`,
  `iff_trans`, and `iff_sym`

Exit condition: Lean has a complete whitelist of proof constants that generated
substitution proof terms may reference.

## M2.2 Type-valued evidence AST

Add a printable evidence AST, not a `Prop` relation.

The AST must include:

- basis leaves, carrying a `BasisName`
- glue nodes for proof composition, including point-level `iff_trans`/`iff_sym`
- binder-level glue such as `Forall_iffTrans_apply`,
  `Forall_iffSym_apply`, `Forall_*Cong`, and `imply_elim`
- enough argument slots to render exact Core type/predicate/proof arguments

This AST is the data the printer consumes. `SubstEquiv` stays as the spec.

Exit condition: the AST can represent known-good proofs such as `memBeta`,
`sepPhiBeta`, and `Forall_exUnionClean`.

## M2.3 Statement and substitution-map renderer

Build a renderer for the proposition being proved, not just the proof body.

For open predicates, emitted Core must close the statement, for example:

```text
Pred.term (Forall I Final
  (Pred.iff (I x Final)
    (P o sigma)
    Q))
```

For point-level facts, emitted Core may be a direct closed `iff`.

The renderer must print:

- right-nested context objects
- lifted substitution maps
- `pair`, `fst`, `snd`
- `Cart.weakening`
- `pointAt`
- `smap`-style composites
- exact Core composition grouping

Exit condition: Lean can render a statement definitionally equal to one existing
handwritten bridge statement.

## M2.4 First emission targets: known-good bridges

Do not start with novel substitutions. First generate `.cor` defs matching
already-derived bridges.

Initial targets:

- `memBeta`
- `memBetaRev`
- `constAtomBeta`
- `sepPhiBeta`
- `atomBeta`
- one binder-level cleaner, such as `Forall_atomSmapClean` or
  `Forall_exMemPhiClean`

Add a generated check file, likely:

```text
ma1/contextual_hol_basis_derivation_check.cor
```

The check file should ascribe generated terms to the handwritten statement
types, like `contextual_hol_regen_check.cor`.

Exit condition: `corecheck contextual_hol_basis_derivation_check.cor` passes.

## M2.5 Formula-driven evidence builder

After known-good bridge emission works, add a structural builder:

```lean
buildSubstEvidence? : ... -> Formula -> Option Evidence
```

It should mirror the formula recursion in `translate_substFormula`, but return
printable evidence data.

Cases:

- atom
- unary predicate slot
- connectives
- quantifiers

Exit condition: selected formula substitutions emit `.cor` proof terms accepted
by `corecheck`.

## M2.6 Mechanical whitelist check

Generated proof files should be checked against the `BasisName.coreName`
whitelist, with separate allowance for primitive logical glue.

Any depth-specific or accidental bridge name should fail the check.

Current status: the generator checks every `Evidence.Proof` against
`BasisName.all`, and raw proof-string escape hatches are rejected.  Primitive
logical glue (`iff_trans`, `iff_sym`, `imply_elim`) is rendered through
`BasisName.coreName` too, so generated proof constants now have a single
machine-readable source of truth.

Exit condition: generated proof terms use the same finite names independent of
substitution depth.

## Immediate implementation order

1. Add finite ctx-lifted basis/glue for the remaining prefix recursive cases:
   `or`, `imp`, `iff`, and `not`.
2. Add generated quantified examples that exercise those cases.
3. Generalize the prefix builder to nested quantifier bodies.
